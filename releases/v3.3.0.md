# 3.3.0

Records and downloads.

- **Archived on / In the archive for.** The Archived Plugins list remembers when each plugin was archived and shows how long it has been there. Both columns sort. Plugins archived before this release show an estimate marked "about".
- **Activity Log.** A new tab records archive, restore, delete, download and rename actions with the user and time. The newest 500 entries are kept on your site, with filters, paging, CSV export and a clear button (clearing is logged).
- **Download as zip.** Each archived plugin has a Download link. The zip has one top-level folder, symbolic links are skipped, and plugins over 200 MB are refused (filterable). It works when `DISALLOW_FILE_MODS` is set because it only reads files.
- **Clean uninstall.** Deleting the plugin removes its own settings, dates and log, and leaves archived plugins in place.
- Deleting from the archive now counts and logs only plugins that were actually deleted.
- Fix (found in review): with `DISALLOW_FILE_MODS` the Archived Plugins screen and Download now stay available read-only. WordPress removes `install_plugins` from everyone in that mode, so viewing now uses `activate_plugins` (network administrators on multisite); changes still need `install_plugins`.
- Fix: the Plugins screen no longer stops users who lack `install_plugins`, such as multisite site administrators.
- Fix: the **Auto-deactivate before archiving** box can be turned off again (an unchecked box was being reset to on). Settings now keep only known values and accept only registered archives.
- Skipped plugins are explained: archiving or restoring onto an existing folder name reports how many were left in place and why.
- Switching the active archive from the list needs a security token.
- Uninstall on multisite removes the plugin's settings from every site.
- Faster Plugins screen: the archive count is cached for ten minutes and cleared after every change; the list code loads only on the plugin's own screens.
- Cleanup: every PHP file passes the WordPress coding standards with zero findings; unused field renderers and commented-out code removed; the list table class is now `HackRepair_Plugin_Archiver_List_Table`.

Validation: PHP syntax lint, shared PHPCS (zero findings), two plain-PHP logic suites, packaging permissions, and a run on a local WordPress site (archive, dates, download, log, CSV export, restore).
