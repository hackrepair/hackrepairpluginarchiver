# 3.3.2

Fixes and polish found by testing every feature on a local site.

- **Delete asks first.** Deleting a plugin from the archive, one at a time or in bulk, now asks for confirmation, because the files are removed permanently. Clear log already asked.
- Fix: settings messages on the Plugin Archiver screen (for example "The new archive could not be created") no longer appear twice.
- Fix: when every selected plugin is skipped because of a folder-name clash, only the reason is shown, not "0 plugins archived successfully" as well.
- Read-only mode (`DISALLOW_FILE_MODS`): the New Archive field is disabled with an explanation, and the Archived Plugins list no longer shows checkboxes, since there are no bulk actions.
- Refused actions now answer with 403 Forbidden (400 for an unknown action) instead of a generic server error.
- **Plugin Check clean-up.** Ran WordPress.org's Plugin Check and fixed what it reported: the archive list no longer calls a private WordPress function (header fields are cleaned by the plugin itself, with the same rules core uses), submitted plugin names and search text are unslashed and sanitized, `Tested up to` now names the major version (7.1), and the unneeded `load_plugin_textdomain()` call is removed because WordPress loads translations for WordPress.org plugins itself. Left as is: a warning that the name and slug contain the word "plugin" (the slug is fixed for an existing plugin).

Validation: PHP syntax lint, shared PHPCS, Plugin Check (no errors), the plain-PHP logic suites, packaging permissions, and a run on a local WordPress site.
